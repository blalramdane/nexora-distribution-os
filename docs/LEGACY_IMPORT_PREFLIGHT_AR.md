## 2. نتيجة CSV العملاء

- 2,128 صفًا؛ لا توجد صفوف ناقصة الاسم أو الهاتف حسب الفحص البنيوي الأولي.
- لا توجد مجموعات أكواد مكررة داخل الملف.
- توجد 8 مجموعات أرقام هاتف مكررة، و8 سجلات بأطوال أرقام غير معتادة (9 أو 12 أو 13 أو 14 رقمًا) تحتاج تطبيعًا/مراجعة.
- أداة `tools/import_iphone_contacts.php` شُغّلت في وضع `DRY_RUN_NO_CHANGES` فقط: اعتبرت السجلات الـ2,128 موجودة مسبقًا، ولم تقترح إضافة أي سجل جديد. **لم يُنفّذ Commit ولم تُكتب بيانات من هذا الاختبار.**
- القرار: عدم إعادة استيراد هذا الملف الآن. يجب التحقق مما إذا كان يمثل جهات اتصال الهاتف السابقة، ومقارنته بدليل المدينة دون دمج تلقائي أو إرسال فواتير إلى أرقام غير مؤكدة.

## 4. حماية الملفات

- أُضيفت قواعد `.gitignore` محددة لاستبعاد ملفات المصدر الحساسة وملفات staging وتقارير الاستيراد المحلية من Git.
- بقيت ملفات المصدر الأصلية في مكانها ولم تُنقل أو تُحذف أو تُعدّل.
- ملفات النص المستخرجة وتقرير JSON تُكتب فقط داخل `legacy-import/almadina-source/`، وهو مجلد مستبعد من Git.
- لا ترفع ملفات العملاء أو المخزون أو تقارير الموردين إلى مستودع عام أو إلى بيئة عرض عامة.

## 5. ما يمكن وما لا يمكن استيراده حاليًا

تم تجهيز staging خام محلي لكل سطر مرقم في ملفات PDF الثلاثة، مع الاحتفاظ بالنص الأصلي ورقم الصفحة والسطر وحالة `needs_manual_column_mapping`:

- `legacy-import/almadina-source/staging-candidates/عملا.csv` — 424 سطرًا مرشحًا.
- `legacy-import/almadina-source/staging-candidates/اصناف.csv` — 1,145 سطرًا مرشحًا.
- `legacy-import/almadina-source/staging-candidates/البضاعة.csv` — 312 سطرًا مرشحًا.

هذه الملفات **ليست ملفات استيراد جاهزة**؛ إنها طبقة مراجعة خام محلية. يلزم قبل الاستيراد:

1. بناء معاينة صفوف منظمة من كل PDF ومراجعة اتجاه الأعمدة والأرقام والأسعار والوحدات يدويًا.
2. فصل العميل عن المورد وفق حقل التصنيف، مع الاحتفاظ بمعرّف المصدر والاسم والهاتف الأصليين.
3. مطابقة الأصناف باستخدام الاسم/الكود/الوحدة والمورد؛ لا يُدمج التشابه النصي وحده تلقائيًا.
4. مطابقة رصيد آخر المدة حسب الصنف والموقع والوحدة. لا تُرحّل الكميات السالبة أو تحويلات الكرتونة/القطعة قبل توثيق القاعدة واعتماد الاستثناءات.
5. مراجعة الأرصدة الافتتاحية وأي فروق مالية. ملفات PDF الحالية لا تكفي وحدها لإعادة بناء تاريخ الفواتير والمدفوعات والذمم؛ نحتاج تصديرًا أصليًا مستقلًا إن كان المطلوب نقل التاريخ المحاسبي.
6. إصدار تقرير معاينة بالمضاف/الموجود/المكرر المحتمل/المتعارض/الناقص، ثم تنفيذ تجربة على قاعدة اختبار معزولة فقط.
7. التوقف بعد التجربة لعرض المجاميع والفروقات والحصول على موافقة صريحة قبل اعتماد أي ترحيل.

## 6. بوابة القرار التالية

**الخطوة التالية المسموحة:** تحويل النص المستخرج إلى ملفات staging CSV محلية، مع تقرير استثناءات، دون كتابة إلى قاعدة التطبيق.  
**غير مسموح في هذه المرحلة:** استيراد العملاء أو الأصناف أو المخزون إلى الجداول التشغيلية، أو تعديل أرصدة/قيود، أو النشر للإنتاج.
