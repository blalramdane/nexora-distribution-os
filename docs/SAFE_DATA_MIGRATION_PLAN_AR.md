# NEXORA Distribution OS — خطة ترحيل البيانات الآمنة

**الحالة:** مرحلة التجهيز وقاعدة الاختبار فقط — لم يتم استيراد بيانات مصدر حقيقية.
**البيئة:** قاعدة MySQL 8.4.11 معزولة باسم `nexora_migration_test` على المنفذ المحلي `13307`، داخل Docker volume مستقل `nexora-migration-test_nexora_mysql_data`.

## 1. ضمانات عدم الإتلاف

- يُعامل برنامج الكاشير وجهات اتصال الهاتف كمصادر قراءة فقط؛ لا تعديل ولا حذف ولا كتابة رجعية إليها.
- لا تُستخدم قاعدة الإنتاج ولا بيانات عملاء حقيقية في بيئة العرض العامة.
- لا يُعتمد أي استيراد قبل تقرير المطابقة وموافقة المستخدم على ملخصه.
- لا دمج تلقائي للسجلات المتشابهة، ولا تعديل للأرصدة أو المخزون بسبب اختلاف غير محسوم.
- يحتفظ كل سجل مستورد بمصدره ومعرّفه الأصلي وبصمة الملف/الدفعة، مع سجل تدقيق.
- إعادة تشغيل الدفعة نفسها يجب أن تُكتشف كبصمة/دفعة مكررة، لا أن تضاعف الفواتير أو الكميات.

## 2. مصادر البيانات المطلوبة

1. **برنامج الكاشير:** الاسم غير معروف حاليًا. نحتاج تصديرًا أصليًا غير معدل بصيغة Excel/CSV، أو نسخة قاعدة بيانات/نسخة احتياطية يتيح البرنامج تصديرها رسميًا. لا نحتاج كلمة مرور الحساب.
2. **جهات اتصال الهاتف:** تصدير VCF/vCard أو CSV من جهات الاتصال. هذا لا يعني أن تيليجرام يتيح أرقام كل من تحدثت معهم؛ نستورد فقط الأرقام المتاحة والمصرح باستخدامها في ملف جهات الاتصال.
3. **الفواتير والأصناف والمخزون:** تصدير مستقل لكل نوع إن أمكن، مع تفاصيل بنود الفواتير، الوحدات/العبوات، المخازن أو الفروع، تواريخ الحركة، والمدفوع والمتبقي. لا يُستنتج المخزون التاريخي من الرصيد الحالي وحده.

## 3. ترتيب التنفيذ

1. استلام نسخ تصدير فقط، وتسجيل اسم كل ملف وحجمه وSHA-256 وتاريخ استلامه، دون فتح المصدر للكتابة.
2. فحص الصيغ والأعمدة والترميز والتواريخ والعملات والوحدات؛ إنشاء نسخة عمل منفصلة مع إبقاء الملفات الأصلية دون تعديل.
3. تطبيع أرقام الهاتف المصرية لأغراض المطابقة فقط، مع الاحتفاظ بالقيمة الأصلية؛ تصنيف التطابق إلى مؤكد/محتمل/متعارض.
4. تجهيز جداول مرحلية (staging) منفصلة لكل مصدر، ثم تقرير معاينة دون إدخالها إلى الجداول التشغيلية.
5. مطابقة العملاء والموردين والأصناف باستخدام الهاتف/الكود/SKU والاسم والوحدة، مع إبراز التطابقات المحتملة يدويًا.
6. مطابقة الفواتير: الرقم والتاريخ والطرف والإجمالي وبنود الفاتورة. فحص المجاميع: مجموع البنود، الخصم، الضريبة، الإجمالي، المدفوع، والمتبقي.
7. مطابقة المخزون حسب الصنف والموقع/المخزن والوحدة؛ لا تحويل وحدات أو تسوية فرق دون قاعدة تحويل موثقة وموافقة.
8. تشغيل تجربة استيراد على قاعدة الاختبار فقط، داخل معاملة قابلة للتراجع لكل دفعة، مع مفاتيح idempotency وسجل تدقيق.
9. إصدار تقرير بعد التجربة، ثم إيقاف التنفيذ لحين مراجعة الفروقات واعتمادها صراحةً.

## 4. قواعد قرار المطابقة

- **مطابق:** مفتاح ثابت متفق عليه والحقول المالية/الكمية متسقة.
- **مرشح تكرار:** تشابه اسم أو هاتف فقط؛ يحتاج مراجعة، ولا يُدمج تلقائيًا.
- **تعارض:** اختلاف رصيد/إجمالي/وحدة/تاريخ/طرف؛ يُعزل ولا يُرحّل حتى يُحسم.
- **سجل جديد:** لا يوجد تطابق موثوق؛ يُعرض كإضافة مقترحة، ولا يُعتمد تلقائيًا.
- **بيانات ناقصة:** سجل لا يملك الحد الأدنى من الحقول؛ يُدرج في تقرير الاستثناءات.

## 5. تقرير المطابقة قبل الاستيراد — خط الأساس الحالي

## 6. شكل التقرير الفعلي المطلوب بعد استلام الملفات

لكل ملف ومجموعة بيانات سنصدر: عدد الصفوف المقروءة، الصفوف الصالحة، المكررات المؤكدة والمحتملة، السجلات الجديدة المقترحة، الحقول الناقصة، التعارضات، إجمالي مبالغ الفواتير، مجموع الأرصدة، وإجمالي كميات المخزون حسب الصنف والموقع والوحدة. سيظهر الفرق العددي والمالي/الكمي بين المصدر والهدف التجريبي، مع قائمة استثناءات قابلة للمراجعة. لن يتم اعتماد أي فرق ضمنيًا.

## 7. المطلوب من المستخدم للخطوة التالية

- تصدير تجريبي صغير من برنامج الكاشير (مثل 10–20 سجلًا من كل نوع، مع إخفاء أي بيانات حساسة إن أمكن) أو نسخة تصدير كاملة تُعالج محليًا فقط.
- ملف جهات اتصال VCF أو CSV من الهاتف.
- اسم برنامج الكاشير إن ظهر في شاشة البرنامج، أو صورة شاشة «تصدير/نسخ احتياطي» دون كلمات مرور أو رموز دخول.

بعد فحص العينة نحدد خريطة الأعمدة وننشئ تقرير المطابقة بالأعداد والفروقات الحقيقية قبل تجربة الاستيراد.
