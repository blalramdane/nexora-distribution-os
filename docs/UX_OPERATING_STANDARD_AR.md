# معيار تجربة الاستخدام والتشغيل — NEXORA Distribution OS

**الحالة:** معيار تصميم وتشغيل مستمر لكل شاشة جديدة أو شاشة يعرضها المستخدم للمراجعة.

## الهدف

النظام مخصص لفريق توزيع عملي؛ لذلك يجب أن تكون كل شاشة مفهومة من أول نظرة، وأن توصل المستخدم للإجراء الصحيح بأقل تنقل ممكن. عند إرسال صورة لأي شاشة، المطلوب مراجعة سير العمل والبيانات والإجراءات والحالات، وليس تغيير الألوان أو ترتيب العناصر فقط.

## قواعد ثابتة لكل شاشة

1. **عنوان يشرح المهمة:** عنوان عربي مباشر، وتحته سطر واحد يوضح ما الذي يمكن إنجازه هنا.
2. **إجراء رئيسي واحد:** أبرز إجراء تالي فقط. الإجراءات الأقل استخدامًا تكون ثانوية أو داخل «أدوات إضافية»، بدون إخفاء وظيفة ضرورية.
3. **خطوات واضحة عند تعدد المراحل:** استخدم 3–5 مراحل مرئية، وأظهر نموذج المرحلة الحالية فقط. بعد نجاح المرحلة انقل المستخدم للمرحلة التالية أو وضّح الخطوة التالية بوضوح.
4. **بحث بدل القوائم الطويلة:** بحث بالاسم والكود والهاتف والباركود أو رقم المستند حسب نوع الشاشة. القوائم الكبيرة تستخدم البحث والترقيم من الخادم؛ لا تعتمد على أول 50 أو 200 سجل فقط.
5. **ملخص مالي أمين:** وضّح هل الرقم إجمالي لكل المؤسسة أم للبحث الحالي أم للصفحة الحالية. لا تجعل الفلتر يغيّر رقمًا معروضًا على أنه إجمالي عام.
6. **صفوف قابلة للمتابعة:** من كل عميل أو مورد أو فاتورة أو رحلة يجب أن يستطيع المستخدم الوصول للسجل الأصلي، والتفاصيل ذات الصلة، والعودة للسياق السابق.
7. **كل الحالات مرئية:** حالة تحميل، حالة فارغة، نجاح، فشل، وتحذير مفهوم مع سبب والخطوة التي تصلحه. لا تكتفِ برسالة عامة مثل «حدث خطأ» إذا كان سبب الرفض معروفًا.
8. **قبل الترحيل المالي أو المخزني:** تحقق من الأطراف والموقع والكميات ووحدة القياس والتكلفة والمبلغ النهائي. اشرح أي اختلاف، وامنع التسجيل غير الصحيح بدل تمريره بصمت.
9. **تتبّع موثوق:** لا تنسب مخزونًا قديمًا لمورد بالتخمين. إذا كانت بيانات المصدر غير متاحة، اعرضه بوضوح على أنه غير منسوب.
10. **مصدر واحد للحقيقة:** الملخصات المالية والأرصدة ومخزون كل موقع تأتي من استعلامات موثوقة ومقيّدة بالمؤسسة؛ لا تجمع أرقامًا من الصفحة الحالية على أنها الرصيد الكامل.
11. **العربية وRTL أولًا:** اتجاه صحيح، عناوين قصيرة، أحجام نص مقروءة، حالات التركيز بلوحة المفاتيح، وأزرار مريحة للموبايل والعمل الميداني.
12. **لا تغيير تشغيلي مخفي:** لا تُجرِ أي ترحيل أو تحديث مخزون نتيجة OCR أو مطابقة مقترحة تلقائيًا؛ مراجعة المستخدم والتأكيد الصريح مطلوبان.

## تدفقات التشغيل القياسية

### البيع

اختيار مصدر المخزون أو الرحلة ← بحث وتصنيف المنتجات ← سلة ووحدات بيع وكميات ← العميل ← الخصم والمدفوع والمتبقي ← مراجعة وتأكيد ← فتح الفاتورة.

### المشتريات

اختيار المورد وموقع الاستلام ← البحث عن الأصناف ووحدة الشراء ← الكميات والتكلفة ورقم فاتورة المورد ← مراجعة الإجمالي ← ترحيل واحد ← فتح ملف المورد/الفاتورة.

### فاتورة صورة أو PDF

رفع الملف ← قراءة OCR ← مراجعة المورد والمخزن والتاريخ والإجمالي ← مطابقة الصنف والكمية والتكلفة مع الأصل ← تأكيد الترحيل. لا يُسمح بالترحيل إذا كان الإجمالي النهائي غائبًا أو لا يطابق البنود.

### الرحلة والعربية

إنشاء/اختيار الرحلة ← تحميل الأصناف من المخزن ← العملاء والزيارات وترتيبها ← المصروفات والتحصيلات ← جرد الكمية الفعلية والنقدية ← مراجعة الفروقات ← تسوية وإقفال.

### العميل والمورد

ملف 360 واحد يجمع التواصل، ملخص الحساب، الفواتير، المدفوعات/التحصيلات، المرتجعات والزيارات ذات الصلة، مع فتح المستند الأصلي وترقيم التاريخ الطويل.

### المخزون

بحث وتصنيفات ← تصفية بالموقع والحالة (متاح/منخفض/نفد) ← عرض الرصيد والتكلفة وقيمة الرصيد ← إجراء واضح لتسوية الجرد مع سبب مسجل، ومنع الرصيد السالب.

## معايير القبول قبل تسليم أي شاشة

- يستطيع مستخدم جديد تحديد الإجراء الأول خلال ثوانٍ دون شرح شفهي.
- البحث يعمل على كامل النتائج في المؤسسة المصرح بها، مع pagination من الخادم عند الحاجة.
- المبالغ والأرصدة موصوفة بنطاقها الصحيح، والفاتورة أو الأصل قابل للفتح.
- الرفض يوضح ما يجب تصحيحه؛ ولا ينتج عنه تغيير جزئي في المخزون أو الحسابات.
- تم اختبار `lint` والبناء واختبار API/المسار المتأثر؛ وأي اختبار متخطى أو اعتماد على MySQL يجب التصريح به.
- لا يعتبر نجاح البناء وحده دليلًا على نجاح التدفق؛ تُستخدم اختبارات المتصفح عندما يكون من العملي تشغيلها على نسخة اختبار معزولة.

## حدود السلامة والإصدار

- تبقى صلاحيات المستخدم وعزل بيانات المؤسسات فعالين في كل endpoint جديد.
- لا يتم تعديل ملف `.env` أو قاعدة المستخدم المحلية الرئيسية لأغراض الاختبار، ولا تُستخدم بيانات الإنتاج في اختبارات قابلة للكتابة.
- لا يتم commit أو push أو deploy أو حذف بيانات بدون تفويض صريح.
- التحسينات المحلية لا تعني اعتماد الإنتاج؛ يجب ذكر أي بوابة محاسبية أو MySQL أو سياسة عمل ما زالت مفتوحة.
